## 클라이언트-서버 모델과 렌더링 방식

### 기본 개념 정리

#### 클라이언트-서버 역할 정의

* **클라이언트**: 요청만 하는 주체 (브라우저)
* **서버**: 요청에 따라 문서를 생성/제공하는 주체

#### 리소스 서버와 API 서버

* **리소스 서버**: 페이지, CSS, 이미지 등 정적 자원 제공
* **API 서버**: 데이터 처리 및 동적 정보 제공

### 렌더링 방식

#### CSR (Client-Side Rendering)

* Next.js에서는 `'use client'` 지시어가 있는 컴포넌트
* 서버는 HTML 뼈대와 JavaScript 코드만 제공
* 실제 UI 렌더링은 클라이언트(브라우저)에서 담당
* 장점: 동적 인터랙션, SPA 경험
* 단점: 초기 로딩 느림, SEO 취약

#### SSR (Server-Side Rendering)

* 서버에서 완전한 HTML을 생성하여 클라이언트에 전송
* Next.js의 기본 Server Component 방식
* 장점: 빠른 초기 로드, SEO 최적화
* 단점: 서버 부하 증가, 인터랙션 지연 가능성

### 서버 사이드 상태 관리

서버 사이드에서 상태 관리란:

* **서버 컴포넌트에서의 데이터 흐름**: 서버에서 데이터를 가져와 렌더링
* **세션 관리**: 사용자 인증 상태 등을 서버에서 관리
* **캐싱 전략**: 데이터 재사용을 위한 캐싱
* **서버 액션**: 클라이언트의 이벤트에 응답하는 서버 측 함수

Next.js에서는 이러한 서버-클라이언트 패러다임을 통합하여, 서버와 클라이언트 각각의 장점을 최대화하는 하이브리드 접근 방식을 제공합니다.
