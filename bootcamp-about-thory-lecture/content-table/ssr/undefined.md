# 리엑트 프로젝트 구조

### 일반적인 접근법 vs 계층화된 접근법

#### 일반적인 접근법:

* Supabase와 같은 DB 서비스에서 직접 REST API 호출
* 컴포넌트에서 모든 데이터 처리 로직 관리
* 단기적으로는 빠른 개발 가능하지만 유지보수 어려움

#### 계층화된 접근법 (현재 프로젝트):

* 3계층 아키텍처를 사용하여 관심사 분리
* API Route(Adapter)를 통해 원격 API 호출을 추상화
* DTO(Data Transfer Object) 패턴으로 데이터 모델 표준화

### 핵심 이점

1. **유지보수성 향상**:
   * 비즈니스 로직과 데이터 접근 로직의 분리
   * API 변경 시 중앙에서만 수정 필요
2. **확장성**:
   * 백엔드 서비스 변경 시에도 프론트엔드 코드 보호
   * 일관된 데이터 구조 유지
3. **테스트 용이성**:
   * 각 계층별 독립적인 테스트 가능
   * Mock 데이터 활용 편리
